# Web-технологии

Оболочка XlsParse: Next.js, React и TypeScript. Демонстрации Экспарса:
самостоятельные HTML-страницы и обычный CSS, разделённый по файлам.

Проект постепенно переходит на «Экспарс»: загрузить Excel с расписанием,
выбрать верхнюю, нижнюю или обе недели и скачать PNG для чата группы.
ЛР 1–8 готовы: HTML-страницы, пример КИ-24, форма, таблица,
CSS-оформление, меню, варианты вёрстки, JS-проверки и импорт Excel.
В ЛР 5–6 показаны преподаватели из Excel: фамилия, инициалы и должность.
ЛР 8 уже читает Excel с преподавателями; создание PNG остаётся следующим этапом.
[Требования к импорту](docs/paroscope-import.md) описывают разбор
преподавателей и других полей. [TODO.md](TODO.md) пока содержит прежнее
техническое задание планировщика и требует отдельного обновления.

Сайт объединяет 10 лабораторных работ в единый отчёт. Готовы работы 1–8:
HTML, CSS, меню, адаптивная вёрстка, основы JavaScript, объекты и массивы.
У каждой работы есть самостоятельная демонстрация и отчёт с исходниками.
Лабораторные 9–10 пока запланированы.
Пункт «Зачёт» — итоговая аттестация, а не отдельная лабораторная.

## Интерфейс XlsParse

Главная показывает прогресс проекта, следующий этап и готовые работы.
В каталоге доступны поиск и фильтры по технологиям; в лабораторных — навигация
по разделам, исходники и самостоятельные демонстрации.

Переключатель солнце/луна меняет дневную и ночную темы. При первом посещении
используется Midnight Blue, выбранный режим сохраняется в `localStorage`
под ключом `XlsParse-theme`. Это настройка оболочки; самостоятельные страницы
Экспарса используют светлую палитру. Все работы доступны
в каталоге. Анимации учитывают системное предпочтение уменьшения движения.

Нажатие на аватар в шапке позволяет выбрать своё фото. Оно обрезается по центру
и хранится только в этом браузере (`XlsParse-profile-photo`), на сервер не загружается.
При наведении или фокусе появляется приветствие, Escape его закрывает.
Готовые работы отмечены зелёным, незавершённые — красным; HTML, CSS и JavaScript
различаются дополнительными цветовыми акцентами.

Шрифт Manrope хранится локально в `src/app/fonts/` вместе с лицензией OFL:
сайт и сборка не обращаются к внешнему сервису шрифтов. Учебные HTML-примеры
ЛР 1–2 сохраняют исходный вид, а печатный отчёт использует светлое оформление
при любой выбранной теме.

## Запуск

Для приложения, генератора примеров и тестов нужен Node.js 22.18+; разработка
и проверка текущей версии выполнены на Node.js 24.
Для импорта Excel нужен Python 3.13. Установите [uv](https://docs.astral.sh/uv/getting-started/installation/)
один раз; команда настройки создаст `.venv`, скачает Python и зависимости парсера.

```bash
npm install
npm run setup:python
npm run dev
```

Откройте http://localhost:3000.
Next.js запускает Python при загрузке Excel; отдельный HTTP-сервис не нужен.
На текущем компьютере окружение уже настроено. Рекомендованные расширения
VS Code — Python и Pylance; интерпретатор проекта задан в `.vscode/settings.json`.

- `/project` — последняя завершённая версия Экспарса, сейчас импорт Excel из ЛР 8.
- `/labs/1` … `/labs/8` — задание, ход работы, исходный код, демо и проверки.
- `/report` — общий отчёт, восемь глав заполнены, остальные пока запланированы.

В ЛР 2–6 браузер требует выбрать файл, переключатели задают вариант недели.
Учебная GET-форма открывает страницу пояснения и передаёт только имя файла
и режим: содержимое Excel не отправляется, PNG пока не создаётся.
В ЛР 4–6 переключатели действительно фильтруют статический пример через CSS
`:has()` и `:checked`; выбранный Excel пока не читается. Сброс очищает файл,
возвращает обе недели и выключает компактный вид.

## Команды

- `npm run dev` — сервер разработки.
- `npm run build` — сборка для публикации.
- `npm start` — запуск собранного проекта.
- `npm run lint` — проверка кода.
- `npm run setup:python` — подготовить `.venv` и установить зависимости из `backend/requirements.txt`.
- `npm test` — проверки JS и интеграционные тесты Python-парсера на XLS/XLSX; нужна `.venv`.
- `npm run labs:generate:js` — пересоздать HTML ЛР 7–8 и учебные объекты ЛР 8
  на основе ЛР 6. JS и CSS редактируются напрямую и генератором не переписываются.
- `npm run labs:generate` — пересоздать HTML-примеры Экспарса для ЛР 1–2;
  используется фиксированный пример КИ-24 на осенний семестр 2026–2027,
  дата запуска не нужна. При обычном запуске и сборке команда не выполняется.
- `npm run labs:generate:css` — пересоздать HTML ЛР 3–6, включая три версии ЛР 6. Расписание берётся
  из `scripts/data/schedule-example.mjs`, таблица ЛР 3 — из HTML ЛР 2.
  После изменения учебных данных сначала запустите `labs:generate`.
  Генератор не переписывает CSS: стили редактируются непосредственно в файлах.
  Преподаватели для ЛР 5–6 берутся из `scripts/data/teachers-example.mjs`;
  это статический образец, а не реализация парсера Excel.

- `public/labs/01/index.html` — структура документа и списки.
- `public/labs/02/index.html` — форма, таблица и изображение.
- `public/labs/02/form-result.html` — пояснение HTML-этапа: Excel не обработан, PNG не создан.

- `public/labs/03/` — способы подключения CSS и каскад.
- `public/labs/04/` — карточки дней, CSS-переключение недель, состояния и блочная модель.

## Заполнение лабораторной

Создайте модуль в `src/data/labs/` по образцу `lab01.ts`, заполните
`contribution`, `task`, `steps`, `result`, `checks` и при необходимости
`sources`. Подключите его в реестре `src/data/labs.ts`.
Статус `done` ставится после проверки демонстрации и заполнения отчёта.
Один компонент `LabReport` выводит эти данные на странице работы и в общем отчёте.

Для демонстрации укажите `demo: { src, title }`, например
`{ src: "/labs/03/index.html", title: "ЛР 3 — подключение CSS" }`.
`Demo` покажет страницу через iframe и добавит ссылку для отдельного открытия.
В следующих работах CSS и JavaScript размещаются рядом с HTML-примером;
обращения к DOM выполняются внутри демонстрации.

Фрагменты `sourceExamples` ссылаются на файл из разрешённого списка
`src/data/lab-source-files.ts` и секцию между комментариями
`<!-- example:название:start -->` и `<!-- example:название:end -->`.
В CSS используются комментарии `/* example:название:start */` и `/* example:название:end */`.
Добавляя новый файл, расширьте реестр: допустимые ключи `file` выведены из него.
Код читается на сервере при сборке из HTML или CSS, ручная копия в отчёте не нужна.
Дополнительные варианты демо, таблицу сравнения и снимки можно задать через
`demoVariants`, `comparison` и `figures`.

Учебное расписание для Экспарса хранится в `scripts/data/schedule-example.mjs`.
Фабрика `createDemoTasks(today)` относится к прежнему планировщику и пока
используется в старых частях оболочки.
HTML работ 1–2 — статические примеры Экспарса по расписанию КИ-24;
работы 3–6 используют тот же пример с CSS. В ЛР 5–6 он дополнен преподавателями.
Чтобы пересоздать первые два примера, измените шаблоны генератора и запустите
`npm run labs:generate`. Команда перезаписывает файлы ЛР 1–2; новые этапы
разрабатываются в отдельных папках и не требуют её запуска.

При изменении реестра `labs` каталог, прогресс, маршрут и общий отчёт
обновляются автоматически. На `/project` выводится последнее демо со статусом `done`.
Отдельная папка маршрута на каждую работу не нужна.

## Единый отчёт

Откройте `/report` и нажмите «Печать / сохранить PDF». В диалоге браузера
можно выбрать сохранение в PDF. При печати скрывается навигация,
а каждая лабораторная начинается с новой страницы. Интерактивные демонстрации
остаются в веб-версии; для печатной версии опишите результаты в `result`.

Данные автора, группы и преподавателя пока не указаны — их нужно заполнить
в `src/data/report.ts`. Титульный лист и оформление необходимо уточнить
по требованиям преподавателя. После заполнения работ удалите пометку о черновике.

## Хранение данных

На этапах 1–7 показан статический пример. В ЛР 7 проверяются имя/размер файла,
работают alert, prompt и confirm. В ЛР 8 браузер проверяет имя/размер и отправляет
файл в `POST /api/schedule`. Next.js передаёт байты через stdin Python-процессу,
получает JSON и возвращает его интерфейсу. Python читает `.xls` через xlrd,
`.xlsx` через openpyxl; `backend/schedule_parser.py` разбирает предметы, недели,
аудитории, преподавателей и подгруппы. Проверены КИ-23, КИ-24 и КИ-25, до 5 МБ.
Модули нужно открывать через `npm run dev`, а не двойным щелчком по HTML.
При нескольких подходящих листах появляется выбор; неподдерживаемые листы
перечисляются в сообщении. Время импорта показывается локально и не определяет
чётность недели. Ошибки сохраняют прежний результат, сброс возвращает пример.
Файл передаётся серверу и обрабатывается в памяти без сохранения на диск.
Аккаунты и БД не нужны. PNG ещё не реализован. SheetJS остался только в
`tests/vendor/` для создания синтетических книг, браузер его не загружает.

При публикации нужен Node.js-сервер с Python и зависимостями. Самостоятельный
статический хостинг не запустит `/api/schedule`. По умолчанию используется
`.venv/Scripts/python.exe` (Windows) или `.venv/bin/python` (Linux/macOS);
другой интерпретатор задаётся серверной переменной `SCHEDULE_PYTHON`.
Папка `backend/` должна находиться в рабочем каталоге сервера, а окружение Python
устанавливается отдельно от Next.js-сборки. Ограничения шаблона и запуск CLI
описаны в [backend/README.md](backend/README.md).

## Проверка

Для ЛР 3–4 пройдены ESLint, production-сборка и браузерная проверка в Chromium:
загрузка CSS, цвета каскада, размеры блочной модели, переключение недель,
клавиатурный фокус, компактный вид, сброс, обязательность файла и GET-форма.
Проверены ширины 320, 390, 768, 1024 и 1440 px, в том числе раскрытые учебные
примеры, страницы результатов, отчёты и `/project`. Существующие тесты
фабрики задач также проходят. В учебных страницах ЛР 3–4 нет JavaScript.

Для ЛР 7–8 проходят Node-тесты (включая прежние): проверка файлов,
чтение синтетических XLS/XLSX, недели и преподаватели, двухстрочные пары,
параллельные подгруппы, консультации, несколько преподавателей в ячейке, пустые блоки,
несколько листов, неизвестные шаблоны и формат даты. В Chromium проверены
настоящие КИ-23.xls, КИ-24.xls и КИ-25.xls, диалоги, безопасный вывод текста Excel, ошибки, сброс
во время чтения, ширины 320–1280 px и отчёты. Сборка и ESLint проходят.
